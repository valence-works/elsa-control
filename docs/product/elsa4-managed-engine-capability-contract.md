# Elsa 4 managed-engine capability contract

**Status:** Design inventory for [#871](https://github.com/valence-works/elsa-control/issues/871). This document does not certify an Elsa 4 image or host as ready for managed use.

This maps the engine capabilities Elsa Control currently depends on for the managed Elsa 3.8 path, then checks for a corresponding Elsa 4/Foundation touchpoint. Control references are pinned to `25536c65cd3400bee32d5829be054c72904a4f7e`; Foundation references and the targeted source review are pinned to `4c002dadbc3e707546fac9fb7f5521dda7557314`. “Missing / unverified” means no matching host integration or extension point was identified at that revision. It is not a claim that no future implementation is possible.

## Capability map

| Required capability | Elsa 3.8 / Control evidence | Elsa 4/Foundation touchpoint at the pinned revision | Mapping result |
|---|---|---|---|
| Health and readiness | Control’s Azure provider probes `GET {workload-origin}/health` before traffic promotion and during monitoring. The response body is an exact `Healthy`, `Degraded`, or `Unhealthy` value; anything else fails closed. See [`AzureBicepProviderRunner`](https://github.com/valence-works/elsa-control/blob/25536c65cd3400bee32d5829be054c72904a4f7e/src/Deployment/ElsaControl.Deployment.Azure/AzureBicepProviderRunner.cs#L1742) and [`IAzureRuntimeHealthProbe`](https://github.com/valence-works/elsa-control/blob/25536c65cd3400bee32d5829be054c72904a4f7e/src/Deployment/ElsaControl.Deployment.Azure/IAzureRuntimeHealthProbe.cs#L5). | Foundation Host exposes [`/health/live` and `/health/ready`](https://github.com/elsa-workflows/elsa-foundation/blob/4c002dadbc3e707546fac9fb7f5521dda7557314/Essentials/apps/Elsa.Foundation.Host/Health/HealthEndpoints.cs#L29). | Configuration and secret references | Control binds handoff trust and grants from server-governed configuration. The platform resolves those references; the identity token endpoint is blocked from workload code. ## Boundary and follow-up

The mapping can identify the required behavior without deciding how an Elsa 4 producer represents it. Until [#870](https://github.com/valence-works/elsa-control/issues/870) resolves the commercial distribution and manifest authority, do not infer that the Elsa 3 Control projection is the Elsa 4 schema, or admit an Elsa 4 release as a managed engine.

The rows marked **missing / unverified** need linked follow-up issues in their owning repositories before #871 can satisfy its issue-filing acceptance criterion. The release-declaration row depends on #870 before its Elsa 4 representation can be specified. #871 also requires Elsa 4 Lead review. None of these entries claims implementation, production evidence, or managed Elsa 4 readiness.
